# nab'd save banner — exact spec

Everything needed to reproduce the save-banner animation 1 for 1, and a way to
prove you have. Nothing here is about the wider brand overhaul; if you also
need the tile, the wordmark, the tray glyph or the asset builds, that is
`docs/overhaul/`.

**Total 4,120 ms.** Do not change it. The sound file is exactly that long and
`nabd_sound.verify()` asserts it.

---

## 1. The files

| File | What it is | Ships? |
|---|---|---|
| `nabd_ease.py` | the eight easing curves | **yes** — shared, never forked |
| `nabd_banner.py` | the timeline: `TRACKS`, `sample(t)`, `assert_invariants()` | **yes** — replaces the old one wholesale |
| `nabd_mark.py` | the artwork paths and the posing arithmetic | **yes** |
| `nabd_mark_frames.py` | build-time flipbook + `index_for(t)` | **yes** |
| `verify_banner.py` | the 1-for-1 check | no — dev tool |
| `make_reference_gif.py` | renders the GIFs below | no — dev tool |
| `reference/` | ground truth to check against | no |

`nabd_banner` imports `nabd_ease` and `nabd_mark`. `nabd_mark_frames` imports
both, but only *inside* `render()` — `index_for()` is pure stdlib, so
`banner.py` can import it at runtime without pulling in svglib.

## 4. The five rules

**The horns never translate.** They scale about their own roots on the ring's
rim, and the only rotation applied to them pivots at the head's *centre* — so
the roots travel along the rim rather than off it. A translate, or a pivot
anywhere else, visibly tears them off the head. This was got wrong twice.

**The turn is a head turn, not a rotation.** A flat shape rotated with
`rotateY` foreshortens uniformly and reads as a squash. A head keeps its
silhouette and moves its *features*: the ring barely changes (scaleX 0.95),
the near eye slides toward the **centre** of the outline — where it faces the
viewer squarest — and the far eye runs out to the edge and compresses to 65%.
Pushing the features the other way, card-style, stops it being a turn.

**The horns lag the head by 45 ms and overshoot.** `sample()` computes this
from where the head *was* (`t - LAG_MS`) rather than keyframing it, so it stays
correct if `TILT_MAX` changes. Do not turn it into a track.

**The head pivots at the neck, not its centre.** `PIVOT = (191.8, 318.0)`.
Rotating about the centre is a spin — the thing the guidelines forbid, and the
thing that turns a ring buffer into a loading indicator. **Never rotate the
ring.**

**Three dials.** `TILT_MAX` 14°, `TURN_MAX` 1.0, `SQUASH` 0.88. Everything
else is computed from them.

## 5. The flipbook

The mark has a pose now, so it can no longer be one cached PNG with a ring
overlay drawn on top. Bake the whole thing at build time:

```
python nabd_mark_frames.py assets/mark --scale 1 1.25 1.5 2
```

254 frames per scale: one resting frame plus three motion windows
(440–908, 1500–2528, 3030–3548). At 30 px these are tiny — the full four-scale
build is about 1,000 PNGs, 610 kB, and 21 seconds.

At runtime:

```python
from nabd_mark_frames import index_for
img = frames[index_for(t)]          # already loaded, indexed by int
```

Two things about the render, both found by running it rather than assuming:

- **The purple field is baked into the frames.** The mark only ever appears on
  the solid card, and baking the background gives clean antialiased edges
  instead of the white fringing you get compositing a keyed-transparent PNG.
  `render(bg=...)` takes a different colour for the rail or the tray.
- **svglib reads the SVG's width as points, not pixels**, so a 60 px request
  comes back 45 px. `render()` rescales the drawing explicitly. If you rebuild
  this path yourself, that is the bug you will hit.

## 5a. What svglib will not do

Found by rasterising the frames and counting ink, after the first pass of GIFs
came back wrong. **The browser preview and the Python build cannot share the
same techniques**, because svglib supports neither of the two the preview used:

| Technique | Browser | svglib |
|---|---|---|
| `stroke-dasharray` + `stroke-dashoffset` | draws the ring on | **ignored** |
| `opacity` on a `<g>` | fades the horns and eyes in | **ignored** |
| `opacity` / `fill-opacity` on a path | — | **ignored** |
| 8-digit hex fill, `rgba()` | — | **ignored** |

All five forms of transparency were measured: every one rasterises fully
opaque. Ported verbatim, that produced a flipbook where the ring was fully
drawn in all 254 frames, the horns sat on screen as permanent 15% stubs, and
the eyes never opened — while every timeline assertion still passed, because
the bug was entirely in the rasteriser and none of the data was wrong.

So `nabd_mark.py` does two things differently from the preview, and both are
load-bearing:

- **`ring_arc(progress)` emits the partial arc as geometry**, computing the end
  angle and the large-arc flag, instead of dashing a full one.
- **`_mix(fg, bg, a)` bakes opacity into the fill colour.** `pose_svg` takes a
  `bg` and mixes the horn and eye fades against it. This is exact, not an
  approximation, because the mark only ever sits on a solid field — which is
  why `render()` bakes the background in anyway.

One consequence: **the horns are drawn under the ring**, where the preview
drew them over it. With opacity baked into the fill, a part-grown horn painted
*over* the rim would leave a mixed-with-field patch where its root crosses the
stroke. Under the ring, the rim covers that overlap with solid art — which is
what true alpha compositing of two same-coloured shapes gives anyway, so the
finished frames match the preview.

`assert_raster()` in `nabd_mark_frames.py` now counts ink at 0.0 and 1.0 for
each of the three channels and fails if any of them does not actually render.
Run it in the build alongside the other two. A data assertion cannot catch
this class of bug; only rasterising and looking can.

## 6. Wiring `banner.py`

Drive it off a wall clock, never a tick counter — a dropped frame must cost a
frame, not shift the whole timeline out of sync with the audio:

```python
start = time.perf_counter()
def tick():
    t = (time.perf_counter() - start) * 1000.0
    if t >= TOTAL_MS:
        root.destroy(); return
    f = sample(t)
    root.geometry(f.geometry(screen_w, screen_h))
    mark.configure(image=frames[index_for(t)])
    root.attributes("-alpha", f.alpha)
    ...
    root.after(8, tick)
```

`Frame.geometry(screen_w, screen_h)` gives the Tk geometry string directly.
Keep a reference to every `PhotoImage`; Tk garbage-collects them silently and
you get a blank card with no error.

`banner.py` stops compositing a ring overlay. It blits `frames[index_for(t)]`.

## 7. The sound is untouched

Every cue lands on a beat that did not move:

| Cue | ms | Beat |
|---|---|---|
| air | 0 | line slides out |
| E3 | 320 | card rises |
| **B3** | 900 | ring closes **and the eyes finish opening** |
| B3 | 3200 | ring winds back |
| E3 | 3630 | card collapses |
| air | 3890 | line withdraws |

`nabd_sound.DURATION_MS` stays 4,120 and the WAVs are not regenerated. The eyes
were deliberately timed to land on 900 so the resolve marks the ring closing
*and* the daemon arriving — one event, one note.

**The wink is silent on purpose.** The sound marks structural events; the wink
is character. Scoring it would need a new 4,120 ms render and would turn a
one-second gesture into a second announcement.

## 8. Proving it is 1 for 1

```
python verify_banner.py
```

Three checks, in order of how much they tell you:

1. Both `assert_invariants()` — the design rules, each of which has been broken
   at least once.
2. **Every channel of `sample(t)` against `reference/timeline.csv` at 4 ms.**
   1,030 rows × 15 channels. A retimed beat, a swapped easing curve or a
   changed dial all show up as a numeric diff with the exact millisecond it
   starts.
3. `index_for(t)` against the same file, so the flipbook contract matches too.

Exit 0 means this tree *is* the reference animation. It is sensitive: dropping
`TILT_MAX` from 14.0 to 13.0 — a change you would not see in a GIF — is caught
at 1,704 ms.

Expected clean output:

```
1. invariants
   nabd_banner      total 4120 ms, eye held shut 216 ms, sound cues land
   nabd_mark_frames 254 frames per scale, windows 440-908, 1500-2528, 3030-3548
2. sample(t) vs reference, every 4 ms
   1030 rows, no channel differs by more than 1e-06
3. index_for(t) vs reference
   1030 rows, no frame index differs by more than 1e-06
OK -- 1 for 1 with the reference.
```

## 9. What will break it

1. Translating the horns, or flexing them about anything but the head's centre.
2. Replacing the head turn with `rotateY` + perspective. It reads as a squash.
3. Rendering pose frames at launch instead of at build time.
4. Changing `TOTAL_MS`.
5. Merging the old `TRACKS` into the new `nabd_banner.py` instead of replacing
   the file.
6. Keyframing the horn lag instead of computing it from `t - LAG_MS`.
7. Driving the loop off chained `after()` callbacks rather than a wall clock.
8. Letting the mark change outside a motion window — `assert_invariants()` in
   `nabd_mark_frames.py` catches this, so run it in the build.
9. Re-introducing `stroke-dashoffset` or any `opacity` into `pose_svg` because
   it looks cleaner. See §5a — svglib drops both silently, and the frames come
   out static with every test still green.

Wire **all three** checks into the build: `assert_invariants()` in
`nabd_banner.py`, and `assert_invariants()` + `assert_raster()` in
`nabd_mark_frames.py`.
